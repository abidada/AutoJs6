## AutoJs6 原生 (C/C++) 代码分布调研

结论：主模块 `app` 没有任何 C/C++ 源码，只有预编译 .so；真正自带 native 源码的只有 `libs/` 下两个子模块。

- `app/src/main/jniLibs/<abi>/` 仅两个 so（4 个 ABI：arm64-v8a / armeabi-v7a / x86 / x86_64）：
  - `libc++_shared.so` — Android NDK 自带 LLVM C++ 运行时，非项目源码
  - `libmediainfo.so` — 第三方 MediaInfoLib-android (olegazyx/MediaInfoLib-android, BSD)，
    项目内只有 Kotlin JNI 封装：`app/src/main/java/org/mediainfo/android/MediaInfo.kt`
    （`System.loadLibrary("mediainfo")`）；上层 JS API 在 `runtime/api/augment/mediainfo/`
- `app/build.gradle.kts` 无 `externalNativeBuild`；`packaging.jniLibs { excludes += "*" }` 参考自 AutoX，
  但实测 APK 仍包含这些 so（arm64-v8a debug APK 约含 13 个 so）
- 真正带 C/C++ 源码并走 CMake+NDK 编译的模块：
  - `libs/imagequant` — PngQuantBridge.cpp(C++17) + external/libimagequant 2.17.0(C) + external/libpng 1.6.49(C)
    → libpngquant_bridge.so / libpng.so / libpng16d.so
  - `libs/rapidocr` — src/main/cpp 下 9 个 cpp（OcrLite/DbNet/AngleNet/CrnnNet/OcrUtils/BitmapUtils/clipper/main.cpp）
    → libRapidOcr.so；opencv-mobile 与 onnxruntime 由 Gradle `newLibDeployer` 从 GitHub Releases 下载
- `modules/` 与 `plugin-api/` 下无任何 .c/.cpp 源码（libChineseConverter.so、libjackpal-termexec2.so 等均为外部引入）
