# 2026-10-08 工作日志

## 修复编译报错：Inconsistent JVM targets (17 and 21)

**现象**：`modules/operit-quickjs` 模块编译报 `Inconsistent JVM targets between Java and Kotlin compile tasks: 17 and 21`（AGP 9 built-in Kotlin 检查，issuetracker 408242956）。

**根因**：
- 本机 Gradle daemon 实际运行在 JDK 21（Android Studio 内置 JBR 21.0.9，另装有 `D:\develop\java\jdk_version\jdk-21.0.7`），故 build-logic 计算的 `gradle.jvm.target.effective` = 21。
- `org.autojs.build.jvm-convention` 插件把 Java/Kotlin 目标统一设为 21（Java 的 compileOptions 用反射**立即**设置；Kotlin 的 jvmTarget 用 `tasks.configureEach` **懒**设置，任务实现时才覆盖）。
- 而 `operit-quickjs/build.gradle.kts` 硬编码了 `compileOptions{17}` 和 `kotlin{jvmTarget=JVM_17}`：
  - Java：构建脚本体里的硬编码 17 在插件立即配置**之后**执行，把 Java 改回 17；
  - Kotlin：插件懒配置在任务实现时**最后**执行，又把硬编码的 17 覆盖回 21。
  - 最终 Java=17、Kotlin=21 → 报错。

**修复**：删除 `modules/operit-quickjs/build.gradle.kts` 里硬编码的 17（`compileOptions` 块 + `kotlin{compilerOptions{jvmTarget}}` 块 + 无用的 `JvmTarget` import），让模块完全遵循 jvm-convention 插件的统一目标（21）。

**约定（供后续参考）**：本项目模块**不要**在 build.gradle.kts 里硬编码 JVM target / compileOptions 的 source/target，统一交给 `org.autojs.build.jvm-convention` 插件管理。若某个模块出现 17/21 不一致报错，先检查该模块是否硬编码了 JVM 版本。

**注意**：CLI 下（无 Android Studio）AGP 会解析成 8.7.3（不识别 compileSdk 37 的 `android-37.0`/`android-37.2` 小版本目录），而 AS 内会解析成 AGP 9。SDK 的 `platforms/` 目录里是 `android-37.0`/`android-37.2`（无 `android-37`）。
