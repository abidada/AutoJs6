## 2. 分析过程概述

### 2.1 分析方法

采用"主线程提纲 + 并行子代理深挖"的方式：

1. **主线程**：读取根构建脚本（build.gradle.kts / settings.gradle.kts / version.properties）、app/build.gradle.kts、README 关键章节，确认包结构与资产目录。
2. **并行探索代理（6 个）**：
   - 代理 A：构建与部署体系（settings.gradle.kts 全文、build-logic、CI、版本机制、ProGuard）
   - 代理 B：UI 与业务功能模块（app/ui、app/project、storage、theme 等全部包）
   - 代理 C：脚本引擎与运行时核心架构（Rhino 定制、引擎链、运行时注入、脚本执行链路）
   - 代理 D：自动化与无障碍服务层（节点查找算法、全局手势、AIDL、Manifest）
   - 代理 E：内置 JS 模块与插件/OCR 系统（assets/modules、pluginclient、plugin-api、modules/libs）
   - 代理 F：版本历史与文档体系（.changelog、.readme、README 结构、.utils、workflows）
3. **补充验证**：README 第 622-648 行"脚本开发辅助"章节原文、@FIXME/@Deprecated 标记扫描、源码规模统计（1731 文件 / 18 万行）。

### 2.2 关键结论

**项目本质**：基于 Rhino 引擎的 Android 无障碍自动化脚本应用；源自 Auto.js 4.1.1 Alpha2，2021/12/01 二次开发，当前 v6.7.0（VERSION_BUILD=3804），21 个版本、约 4.3 年迭代。

**核心架构**：
- 四层架构：UI 层（MainActivity 四 Tab + 编辑器/日志/设置/悬浮窗）→ 引擎层（ScriptEngineService/Manager + RhinoJavaScriptEngine + LoopBased 驱动）→ 运行时层（ScriptRuntime + 50+ 内置模块声明式注入）→ 自动化层（AccessibilityServiceUsher + UiObject 节点模型 + GlobalActionAutomator 手势）。
- v6.6.0 重大变更：内置 API 由 assets JS 文件全面 Kotlin 化，改用 `Augmentable.kt` 声明式注入；新增 RapidOCR 引擎。
- v6.7.0 亮点：插件中心、文件历史/回收站、Paddle OCR 插件、Rhino 2.0.0-SNAPSHOT、Gradle 9 适配。

**关键技术**：
- Rhino 解释模式（isInterpretedMode=true）+ Continuation 协程 + Looper 线程驱动脚本执行。
- 无障碍节点查找：UiObject 包装 AccessibilityNodeInfoCompat + Selector（LinkedList<Filter> 逻辑与）+ BFS/DFS 遍历 + NodeInfo 回收复用。
- 全局手势：dispatchGesture + GestureDescription，VolatileDispose 同步等待。
- 构建体系：settings.gradle.kts 实现"平台探测 → 版本自动匹配"引擎，gradle/data 兼容表 + .utils 爬虫自动化维护。
- 双 OCR（RapidOCR/PaddleOCR）+ MLKit 三引擎，双插件通道（DevPlugin VSCode 远程 / plugin-api AIDL）。

**主要技术债务**：log4j 1.x 高危 CVE（5 个）、isMinifyEnabled=false（无混淆）、com.stardust 旧包与 org.autojs 新包镜像、Rhino SNAPSHOT 依赖、测试几乎空白（androidTest 仅 1 文件）、离线文档与 5MB 补全索引打进 APK。
